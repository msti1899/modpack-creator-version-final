## Specs

- S1: Approved roadmap milestone 4: "One draft pack per group, owner-only edits, exact approved mod/dependency versions, reuse of existing Modrinth resolution/export. Failed writes leave no partial selection."
- S2: Owner decision of 2026-11-12: a draft's Minecraft version or loader may change only when the entire explicit selection remains compatible. An incompatible change is rejected without deleting or automatically substituting any approved version.
- S3: Existing D2: "Confirm required dependencies with the owner before adding them. If the owner declines them, cancel the proposed mod addition." Saving accepts an explicitly supplied complete version selection and never silently resolves or adds dependencies. Exact Modrinth version IDs stay pinned; public resolution and export behavior is unchanged.
- S4: Existing D3/D5: "Initially, each group has one modpack and an owner." "Only the owner edits the group's modpack." "If the owner is the only member and leaves, delete the group and its modpack rather than archiving them." Check isolation, ownership transfer, cascading group deletion and atomic failure. Clerk remains the identity provider; forward the caller's token with a publishable key, never a service-role credential.
- S5: Preserve backend-only roadmap boundaries: "Frontend, CD, CurseForge, multiple groups per user, multiple packs per group, and the desktop launcher remain outside this roadmap's current scope." Publication, active versions and sharing remain milestone 5. Hosted work was separately authorized for the selected test project, limited to reading state, applying only the new draft migration, and creating, verifying and removing bounded disposable fixtures; no resets, unrelated data, Clerk changes, commits or publication.

Implementation choices (not additional product requirements): lazy creation on first
save; current group members can read and export the group's draft while outsiders
cannot; explicit whole-selection replacement; an integer revision compare-and-swap
rejects stale tabs; the existing group row lock serializes save against transfer and
deletion. Export presentation fields remain request inputs, not publication records.
